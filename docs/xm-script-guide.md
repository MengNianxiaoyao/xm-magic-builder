# XMSeer 魔法脚本编写说明

本文只说明由编辑器生成的 `.xm` 脚本格式与命令写法，供编写或分析脚本使用。

## 1. 基本语法

- 一行一条指令：`关键字=内容`，例如 `延时=1000`。
- `|` 用于分隔字段；每个命令的字段数量和含义不同，按第 2 节对照。
- `{}` 表示列表，元素之间用 `,` 分隔，例如 `{1,0,1}`、`{0,0,0,999999}`。
- `[]` 表示变量或表达式引用，例如 `[i]`、`[培养精灵]`、`[变量1]`。
- `#<...>#` 表示简单数值表达式，例如 `#<3*2+1>#`。
- `\r\n` 是字面转义，用于信息输出换行，不是真实换行符。
- `魔法管理` 必须是文件第一行。
- `判断循环体`、`计次循环体` 通过 `头部` / `尾部` 成对出现，按行序配对。
- `自定义出招` / `自定义魔法` 的最后一个字段是十六进制内容，可能很长，按不透明数据看待。

## 2. 命令格式

### 发包与延时

```
发包=<内容>
延时=<毫秒>
对战延时=<毫秒>
```

延时默认 1000。

### 精灵操作

```
精灵首发=<精灵ID>
精灵切换-ID=<精灵ID>
精灵切换-位置=<位置>
设置背包=<ID1>|<ID2>|...
设置背包=<ID1>(<等级1>)|<ID2>(<等级2>)|...
设置背包=还原背包
```

例：

```
设置背包=3022|3437|3460
设置背包=100(10)|110(20)
```

第二种写法指定了等级：ID 100 取 10 级，ID 110 取 20 级。括号内为等级；不写等级时不限制等级，实际取该 ID 中获得时间最早的那只。这里的 `|` 是背包 ID 分隔符，不是行的字段分隔符。

背包共 12 个位置：前 6 只为出战精灵（强制），后 6 只为待命精灵（不强制）。出战不满 6 只、还要设置待命精灵时，用 `0` 填补空位。

### 对战操作

```
接管对战=<对战包>
使用技能=<技能ID>
使用技能=撤退
使用道具=<道具ID>
战前准备=领取绿火
战前准备=压血
战前准备=全精灵恢复
```

火类型可取：绿火、金火、紫火、蓝火。

常用对战道具 ID：

```
初级体力药剂  300011
中级体力药剂  300012
高级体力药剂  300013
超级体力药剂  300014
永寒体力药剂  300079
上等体力药剂  300157
初级活力药剂  300016
中级活力药剂  300017
高级活力药剂  300018
超级活力药剂  300019
全能恢复药剂  300701
```

### 循环体

```
出招循环体=头部
出招循环体=尾部

对战循环体=对战胜利头部
对战循环体=对战未触发尾部

判断循环体=头部|<发包参数>
判断循环体=头部
判断循环体=判断真[级别]|{条件}
判断循环体=且|{条件}
判断循环体=或|{条件}
判断循环体=判断假[级别]
判断循环体=尾部
判断循环体=跳出循环

计次循环体=头部|<标识>|<指定值>|<初始值>
计次循环体=尾部|<标识>
```

例：

```
计次循环体=头部|标识1|[j]|[i]
计次循环体=尾部|标识1
```

出招循环体仅在对战状态触发，头部与尾部之间的内容会连续执行，直到当次对战结束。

对战循环体循环执行头部与尾部之间的语句；执行到尾部时判断，若结果符合当前条件类型则跳出。若从头部到尾部一次对战都未触发，也会直接跳出以避免死循环。

`判断循环体=头部|<参数>` 的参数为空时写作 `判断循环体=头部`。

判断循环体用于收包判断：头部发送参数包并接收返回包，头部与尾部之间用判断真/判断假做逻辑判断。一个层级可以有多个判断真，但只能有一个判断假。

头部发包参数：多个包用 `|` 隔开，不支持携带变量；需要携带变量时，用文本型变量配合“游戏收包主体文本返回”获取收包参数。

- 级别 1 不写数字，2–5 写成 `判断真2`、`判断假3`。
- 且/或追加到当前判断真行；且的优先级高于或，可用 `()` 提高优先级。
- `判断假` 单独一行，不带条件，表示 else 块，块内可以继续添加新的判断。
- 条件组格式：`{左操作数,比较,右操作数}`。

操作数写法：

| 类型 | 写法 | 示例 |
| --- | --- | --- |
| 参数 | `收包,进制,起始,结束` | `1,十六进制,1,1` |
| 文本变量参数 | `[变量],进制,起始,结束` | `[1],十六进制,1,1` |
| 整数变量 | `[变量]` | `[1]` |
| 数值 | 数字 | `100` |

比较符：小于、等于、大于、小于等于、大于等于、不等于。

10 种类型对应的操作数组合：

| 类型 | 左 | 右 |
| --- | --- | --- |
| 参数比较数值 | 参数 | 数值 |
| 参数比较参数 | 参数 | 参数 |
| 参数比较整数变量 | 参数 | 整数变量 |
| 参数比较文本变量参数 | 参数 | 文本变量参数 |
| 整数变量比较数值 | 整数变量 | 数值 |
| 整数变量比较整数变量 | 整数变量 | 整数变量 |
| 文本变量参数比较数值 | 文本变量参数 | 数值 |
| 文本变量参数比较参数 | 文本变量参数 | 参数 |
| 文本变量参数比较整数变量 | 文本变量参数 | 整数变量 |
| 文本变量参数比较文本变量参数 | 文本变量参数 | 文本变量参数 |

例：

```
判断循环体=判断真|{1,十六进制,1,1,小于,1}|且|{[1],十六进制,1,1,小于,[1],十六进制,1,1}
```

计次循环体语义：初始值固定从 1 开始，赋给头部的初始值变量；指定值在第一次执行到头部时捕获，循环内不再改变；每次执行到尾部时初始值 +1，若小于等于指定值则回到头部，否则跳出。头部与尾部用相同标识配对，嵌套时用不同标识区分。

例：指定值 `[j]=5`、初始值变量 `[i]`，循环体执行 5 次，`i` 依次为 1..5，第 5 次到尾部时 `i=6>5` 跳出。

### 野怪操作

```
野怪操作-对战=<地图ID>|<精灵ID>
野怪操作-捕捉=<地图ID>|<精灵ID>

跳图对战一次或捕捉一次野怪；地图 ID 与目标精灵 ID 必须填写正确且不能为空。对战出招使用脱机内置默认出招。跳图走后端发包，若在登录器或 Unity 助手中执行魔法会卡界面。
```

### 变量

```
变量=<类型>|<变量名>|<变量值>|<自定义值>
变量=清空变量
```

- 类型为 `整数型` 或 `文本型`。
- 前三段固定：类型、变量名、变量值。
- 第四段是自定义值；当变量值不是“自定义值”时通常为占位或该类型对应的值。
- `精灵属性查询返回` 的第四段格式为 `{<自定义值>,<属性ID>}`：

```
变量=整数型|<变量名>|精灵属性查询返回|{<自定义值>,<属性ID>}
```

属性 ID = 类型基数 + 属性偏移：

- 类型基数：基础 10、PVE 20、PVP 30
- 属性偏移：体力 1、攻击 2、防御 3、特攻 4、特防 5、速度 6

例：`变量=整数型|数值|精灵属性查询返回|{0,11}`（基础 + 体力）。

### 信息输出

```
信息输出=<内容>
```

内容支持 `{...}`、`[...]`、`#<...>#` 占位符，换行写 `\r\n`。例如：

```
信息输出=\r\n测试输出{1,十六进制,1,1}个,\r\n测试输出[变量1]
```

说明：

- 右下角输出信息。
- 判断循环体收包返回的参数用 `{1,十六进制,1,1}`。
- 文本型变量的收包返回参数用 `{[变量],十六进制,1,1}`。
- 单纯输出变量用 `[变量名称]` 指代。
- `#<...>#` 会对其中内容做简单表达式运算。

### 自定义出招（.xmcus）

```
自定义出招=<对战包>|<文件名>|<hex>
变量=文本型|<变量名>|自定义文本|<hex>
自定义出招=<对战包>|<变量名>.xmcus|[<变量名>]
```

- 第一行：导入并直接使用。
- 第二行：把出招文件存成变量。
- 第三行：使用已有变量。

### 自定义魔法（.xmgic）

`<p>` 为传入当前魔法变量，`<r>` 为返回调用魔法变量，取值都是 `0` 或 `1`。

```
自定义魔法=<p>|<r>|<密码>|<文件名>|<hex>
自定义魔法=<p>|<r>|明文|<变量名>.xmgic|<前缀><GBK hex>
变量=文本型|<变量名>|自定义文本|<hex>
自定义魔法=<p>|<r>|<密码>|<变量名>.xmgic|[<变量名>]
```

- 密码为空时该段留空。
- 明文前缀固定为 `35383444364436313637363936334333463743454334`，后面是明文按 GBK 编码后的十六进制。

### 魔法管理

必须位于第一行：

```
魔法管理={端口限制=<0|1|2>|当前版本=<主>.<次>|接口参数=<值>|接口类型=0|版本控制1=<0|1>|版本控制2=<0|1>|本地黑名单=<值>|Appid=<值>|赞助免费=<1|30|90|365|0>}
```

- 端口限制：0 不限、1 限 Unity 端、2 限 Flash 端。
- 赞助免费：1 不限制、30 月卡、90 季卡、365 年卡、0 禁止。

### 精灵培养

```
精灵培养={精灵ct=<值>|结果=<变量>|是否更换={<9 个 0/1>}|是否强制={<9 个 0/1>}|等级=<100|1>|技能={<4 项>}|学习力={<6 项>}|天赋=<整数>|性格={<文本>}|刻印={<刻印1,刻印2,刻印3,开孔>}|抗性={<3 项>}|体力上限=<整数>|战队加成={<6 个 0/1>}}
```

字段定义：

| # | 名称 | 值 |
| --- | --- | --- |
| 1 | 精灵ct | 原样，通常为 `[培养精灵]` |
| 2 | 结果 | 结果赋值变量，通常为 `[i]` |
| 3 | 是否更换 | 9 个 0/1 |
| 4 | 是否强制 | 9 个 0/1 |
| 5 | 等级 | `100`（1v100）或 `1`（1v1） |
| 6 | 技能 | 4 个整数；技能4 为 999999 表示不更换 |
| 7 | 学习力 | 6 个整数：体力、攻击、防御、特攻、特防、速度 |
| 8 | 天赋 | 整数 |
| 9 | 性格 | `{原文}`，例如 `{1,8}`，不转数字 |
| 10 | 刻印 | `{刻印1,刻印2,刻印3,开孔}`，开孔为 0/1 |
| 11 | 抗性 | `{致命伤害,固定伤害,百分比伤害}`，每项 0/5/35 |
| 12 | 体力上限 | 整数 |
| 13 | 战队加成 | 6 个 0/1：体力、攻击、防御、特攻、特防、速度 |

生成规则：

- 字段 1–4 永远存在。
- 字段 5–13 只有在对应的 `是否更换` 为 `1` 时才写出：
  - `是否更换[1]` → 等级
  - `[2]` → 技能
  - `[3]` → 学习力
  - `[4]` → 天赋
  - `[5]` → 性格
  - `[6]` → 刻印
  - `[7]` → 抗性
  - `[8]` → 体力上限
  - `[9]` → 战队加成
- 因此缺少某个字段，表示本次不处理该项，而不是值为空。
- 生成前会校验：精灵ct 不能为空，9 个是否更换至少勾选一项。
- 界面初始值：`精灵ct=[培养精灵]`、`结果=[i]`、等级 100、技能 `0,0,0,999999`、学习力全 0、天赋 0、性格空、刻印 `0,0,0,0`、抗性 `0,0,0`、体力上限 0。

示例：

```
精灵培养={精灵ct=[培养精灵]|结果=[i]|是否更换={1,1,1,1,1,1,1,1,1}|是否强制={1,1,1,1,1,1,1,1,1}|等级=100|技能={0,0,0,999999}|学习力={0,0,0,0,0,0}|天赋=0|性格={1,8}|刻印={0,0,0,1}|抗性={0,0,0}|体力上限=0|战队加成={1,1,1,1,1,1}}
```

## 3. 格式化后的写法

编辑器格式化会统一这些细节：

- 全角转半角：`＝`、`｜`、`｛｝`、`，` 等。
- 别名替换：`forstart` → `计次循环体=头部`、`forend` → `计次循环体=尾部`、`whilestart` → `判断循环体=头部`、`whileend` → `判断循环体=尾部`、`if` → `判断循环体=判断真`、`else` → `判断循环体=判断假`、`and` → `且`、`or` → `或`、`break` → `判断循环体=跳出循环`。
- `判断循环体` 行补齐或压缩 `|`。
- `精灵培养` 行统一为 `精灵培养={k=v|k=v}`：去掉分隔符两侧多余空格，列表内部 `{1, 0}` 变为 `{1,0}`，保持字段顺序，不重排。

## 4. 编写与解析注意

- 先取行首到第一个 `=` 作为命令，再按该命令的语法解析剩余部分。
- `|` 的含义取决于命令；`设置背包`、`自定义出招`、`自定义魔法` 的值内部也有 `|`。
- `[...]` 是变量/表达式，不要当普通文本。
- 十六进制字段按不透明数据读取，不要截断或按字符分析。
- 循环体按 `头部` / `尾部` 配对，结合行序判断作用域。
- `魔法管理` 只应在第一行；出现在其他位置属于异常。
- 精灵培养先看字段 3 的 9 个开关，再判断字段 5–13 是否存在。
